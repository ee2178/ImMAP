# LGGS: the port against the paper and against Sljiva's runs

*2026-11-09.*

## References

- **The paper.** Janjušević, Chandarana, Wang, Feng, **"LGGS: Longitudinal MRI Reconstruction via
  Guided Group Sparsity"**, arXiv [2610.22643](https://arxiv.org/abs/2610.22643) (v1, 15 Oct 2026).
- **Sljiva** (`github.com/nikopj/Sljiva`, the first author's research repository, checked out at
  `~/Desktop/Sljiva`, last commit 2026-06-22). The runs behind the paper's results are the ones
  `scripts/compute_stats_longi.jl` and `figs/longiLGGS_*` evaluate:
  - `LGGS-MCLongiBrainV2V{6,8,10,12}U-ng`, with 1 / 3 / 5 guides;
  - `LGGS-MCLongiBrainV2V{6,10,12}U-pi-ng3-ws15`, labelled "LGGS-3".

  Both families were generated by `scripts/makeconfigs_longi.jl` on top of
  `config/guided_lpdsnet.yaml` as of April 2026 (commit `6f10e63`). `trained_nets/` there only
  links to an HPC path, so the trained runs themselves are not in the checkout.

**Where the paper's text and the code behind its numbers disagree, Sljiva's evaluated configs
are the better reference** for anything compared against the paper's results.

## Changes on 2026-11-09

### 1. Tied transforms and gamma are forced

`models/guided_lpds.py::tie_transforms_`, called by every `LGGSNet`, shares W_theta, W_phi,
W_alpha, W_beta **and gamma** across the K layers. eta, theta, A, B, tau and rho stay per layer, as
in Sljiva. `tie_transforms=False` is refused.

At paper size this gives 1.04 M parameters (real W's), against Table S1's 1.08 M (which would fit
complex W's). Before the change it was 2.30 M.

**Consequences:**
- **Old checkpoints:** any LGGS checkpoint trained before this date (the knee `lggs` run, the
  NYUMets `SBUnetLGGS` runs) has untied W's and does **not** load. `load_state_dict` raises a
  clear error rather than writing every layer's copy into the one shared tensor. Retrain, or
  check out an older commit to evaluate them.
- **gamma only matters on the gather backend,** which blends adjacencies. The triton backend
  re-caches instead of blending (see below).

### 2. A noise-adaptive threshold, as in Sljiva

`LGGSNet(prox_degrees=...)` sets the polynomial degree in sigma of the prox threshold tau
**alone**. `degrees` keeps setting the step sizes eta, theta, and `prox_degrees=None` (the default)
follows `degrees`, so the NYUMets `SBUnetLGGS` configs (`degrees: 1`, steps included) are
unchanged.

Sljiva's runs use `degrees: 1`, which reaches only the GT's tau (`src/networks/lpds.jl`); the
step sizes are degree 0. The knee cells (`LGGS_PARAMS`, `lggs_defaults`) now carry that split,
`degrees: 0, prox_degrees: 1`. The threshold starts constant (slope 0) and learns its slope from
the per-sample noise level the trainer passes. The fused planar clip kernel accepts a per-sample
threshold (B, M, 1, 1), so the fast path is kept.

### 3. The optimiser recipe: reverted for now, one switch for the next sweep

For a short while on 2026-11-09 every cell carried Sljiva's recipe. That was **reverted**: the
running sweep was launched with the grid's, and what matters is that every cell shares one
recipe. `scripts/make_guided_recon_configs.py` now has `TRAIN_RECIPE`:
- **`"grid"` (in force):** the mg grid's per-model values, exactly as before. Adam 5e-4 (LGGS
  2e-4), cosine to 1e-6, clip 0.05.
- **`"sljiva"`:** Sljiva's `config/train.yaml` for every cell at once. Cosine 4e-4 -> 2e-6 over
  3e5 steps, warmup 0, global-norm clip 1 (torch's `clip_grad_norm_` is the same rule).

**TODO, next sweep:** set `TRAIN_RECIPE = "sljiva"`, for all cells together. `lggs_paper` follows
the switch like every other cell.

### 4. The paper-alignment switches (all off by default)

Each has a key in `model.params` (or `data.*` for the guide slices), and the `lggs_paper` cell
turns them all on:
- `guide_window: 3`, `data.*.guide_slices: 3`, `guide_mean: joint`;
- `dK: 1` with `adj_blend: false`;
- `self_sim_fun: distance`, `similarity_scale: none`, `z_init: zero`.

**`lggs_paper` reproduces the paper's TEXT, not Sljiva's evaluated runs.** For a comparison
against the paper's numbers, `lggs` (now tied, with the shared recipe) is the closer match.

**Guide slices.** Each of PD slices z-1, z, z+1 is combined with the offline ESPIRiT maps of the
same slice, from the PDFS map file. The single-slice path keeps using the target slice's online
maps.

**Behaviour found while testing:**
- **`z_init: zero` only matters with several coils.** With E = Identity or single-coil masked
  FFT, the first sweep from (y~, 0) is exactly the cold start. With the knee data's 15 coils it
  is a real gradient step.
- **The two self similarities coincide at initialisation,** because W_phi starts equal to
  W_theta.

## Still different from Sljiva's evaluated runs

- **gamma blending on triton.** Sljiva blends the adjacency every 5 layers. Our fused backends
  (and the materialised window) replace it instead, so `dK=5` on triton is not Sljiva's model.
  Gather blends correctly.
- **Guide slices at volume edges:** Sljiva shifts the window inward, `lggs_paper` repeats the edge
  slice. Irrelevant for training slices 12-25.

## Not verifiable

- **A newer guide window.** The checkout's later base config moved the window from 15 to 9, and
  the paper's W_g = 3 may come from runs after June 2026. Pull Sljiva to check.
- **Stride, the estimate of mu, real vs complex W's, initial values.** See the table above; the
  port keeps its choices.
